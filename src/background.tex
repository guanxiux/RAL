\subsection{Masked Convolution}
\label{sec:bg:masked}

Convolution runs inside the perception-action loop of many vision
applications~\cite{nanoflownet,fastdepth,bisenet,densefusion,contactgraspnet},
where per-frame inference latency bounds system
responsiveness~\cite{pampc,perclatency,eventavoid,dronerace}.
To cut this latency, masked convolution exploits dynamic spatial sparsity: an
upstream policy emits a spatial mask, and the operator computes only the marked
positions. The mask comes from sources including event-camera
increments~\cite{asyncsparse,evconv}, temporal residuals between video
frames~\cite{cbinfer,skipconv,deltacnn,motiondelta,sparsetem}, or learned input-dependent
gates~\cite{sact,sai,dgnet,dynconv}. These sources differ in sensing
modality and policy, but all expose the same dynamic spatial sparsity on a dense 2D
feature grid, so a single masked-convolution runtime serves them all.

\begin{figure}[b]
  \centering
  \includegraphics[width=\columnwidth]{figures/tikz/bg_conv.pdf}
  \caption{Masked convolution and its dense execution. Each output $y_p$ aggregates its receptive
  field $\mathcal{N}(p)$ in $\mathbf{x}$ with the weights $\mathbf{f}$.
  Dense convolution computes every output in tiles of contiguous positions,
  which keeps loads coalesced and each weight tile reused across the tile, so
  it runs at high throughput; but only the outputs active in $M_{out}$
  (colored) are required, and the throughput spent on the rest (dotted) is
  wasted.}
  \Description{An input grid, a kernel, and an output grid whose active positions
  are colored and inactive positions dotted; a dashed box marks the receptive
  field of one active output.}
  \label{fig:masked-conv}
\end{figure}

Masked convolution retains dense tensor layouts and arithmetic, restricting
only which output coordinates are computed (Figure~\ref{fig:masked-conv}). It operates on an input
feature tensor $\mathbf{x}\in\mathbb{R}^{H_{in}\times W_{in}\times C_{in}}$, a
weight tensor $\mathbf{f}\in\mathbb{R}^{k\times k\times C_{in}\times C_{out}}$ of
kernel size $k$, and an output
$\mathbf{y}\in\mathbb{R}^{H_{out}\times W_{out}\times C_{out}}$ on a coordinate
grid $\mathcal{G}=\{1,\ldots,H_{out}W_{out}\}$, where each coordinate
$p\in\mathcal{G}$ indexes a spatial position $(h,w)$ and has a
$k\times k$ receptive field $\mathcal{N}(p)$ in $\mathbf{x}$. An upstream policy
marks the coordinates to compute in an output mask
$M_{out}\in\{0,1\}^{H_{out}\times W_{out}}$. Spatial gating predicts $M_{out}$
directly; event and temporal policies instead supply an input mask
$M_{in}\in\{0,1\}^{H_{in}\times W_{in}}$ whose active positions propagate their
influence along the receptive field, so $p$ stays active whenever any input in
$\mathcal{N}(p)$ is active,
\begin{equation}
  M_{out}[p] =
  \begin{cases}
    1, & \exists\, r\in\mathcal{N}(p)\ \text{s.t.}\ M_{in}[r]=1,\\
    0, & \text{otherwise.}
  \end{cases}
  \label{eq:mask}
\end{equation}
$M_{out}$ thus identifies the output positions that the execution path is required
to compute, each by aggregating $\mathbf{x}$ over $\mathcal{N}(p)$ with the weights
$\mathbf{f}$.

An execution path issues computation over a sequence of position slots
$\mathcal{C}$, where each slot is drawn from
$\mathcal{G}\cup\{\bot\}$; $\bot$ denotes a padding slot that carries no
output coordinate. The path must satisfy the \emph{coverage contract}: every
active coordinate is included,
$\{p : M_{out}[p]=1\}\subseteq\{c\in\mathcal{C}:c\ne\bot\}$.
For each non-$\bot$ slot $p\in\mathcal{C}$ it computes
\begin{equation}
  \mathbf{y}[p] = \sum_{i=1}^{k^2}
  \mathbf{x}[\mathcal{N}_i(p)]\,\mathbf{f}_i,
  \label{eq:conv}
\end{equation}
where $\mathcal{N}_i(p)$ is the $i$-th position in $\mathcal{N}(p)$ and
$\mathbf{f}_i\in\mathbb{R}^{C_{in}\times C_{out}}$ the corresponding weight
slice. How unrequested positions are treated is policy-specific: event and
temporal execution retains prior state, while learned gating merges results
into a residual. Coverage is therefore the operator-level correctness
condition; the policy determines the treatment of all other positions.
Beyond coverage, a path may issue inactive or $\bot$ slots; dense
convolution is the extreme where
$\{c\in\mathcal{C}:c\ne\bot\}=\mathcal{G}$. The policy fixes the accuracy
and required work.

Existing systems execute a mask along one of two paths. \emph{Tile
skipping}~\cite{sbnet,skipconv,evconv,dynaspa,motiondelta,sparsetem} (Figure~\ref{fig:tile-skip}) inherits the dense pipeline's tile-based computation without additional metadata passes, skipping a tile only when all its coordinates are inactive and
otherwise computing the whole tile; DeltaCNN~\cite{deltacnn} fuses a selective
path into the kernel, taken when a tile is estimated to be mostly empty, to cut
wasted work. \emph{Gather-scatter}~\cite{sai,dgnet}
(Figure~\ref{fig:gather-scatter}) instead abandons the dense pipeline: it extracts exactly the active
coordinates into a packed representation, runs a separate GEMM, and scatters
the results back, removing the inactive arithmetic but adding extraction,
irregular access, and writeback overhead; DynConv~\cite{dynconv} adopts a model structure suited to gather-scatter, where one gather feeds several consecutive layers before a single
scatter, amortizing that overhead.

A policy fixes the active ratio $\alpha$, defined as the fraction of output-grid positions marked active, whereas a concrete execution path determines the useful-compute ratio $\eta$, defined as the fraction of issued slots that correspond to required outputs:
\begin{equation}
  \begin{aligned}
    \alpha &= \frac{\|M_{out}\|_0}{|\mathcal{G}|},
    & \eta &= \frac{\|M_{out}\|_0}{|\mathcal{C}|}.
  \end{aligned}
  \label{eq:efficiency-framework}
\end{equation}
For $|\mathcal{C}|>0$, an ideal path achieves $\eta=1$ by issuing only required outputs; dense convolution, which issues the entire grid, has $\eta\approx\alpha$. An execution path also determines its throughput $T$, which combines with $\eta$ to yield the effective throughput $T_{\mathrm{eff}}$:
\begin{equation}
  \begin{aligned}
    T &= \frac{2|\mathcal{C}|k^2 C_{in} C_{out}}{t},
    & T_{\mathrm{eff}} &= \eta T.
  \end{aligned}
  \label{eq:efficiency-framework-throughput}
\end{equation}
where \(t\) denotes the latency of the execution path, including auxiliary mask and coordinate processing, \(k\) is the filter kernel size, and \(C_{in}\) and \(C_{out}\) are the input and output channel counts respectively. The factor of two counts each multiply-accumulate as two FLOPs. Consequently, \(T_{\mathrm{eff}}\) directly characterizes the processing rate of required outputs and therefore determines the realized latency.

\subsection{Distinction from Related Sparse Execution}
\label{sec:bg:related}

\sysname differs from other sparse-execution work in representation and
sparsity type. 3D sparse-convolution
systems~\cite{spconv2,torchsparsepp,torchsparse,minuet,minkowski,submanifold}
operate on sparse point-cloud coordinates; sparse matrix
multiplication~\cite{dtcspmm,maxkgnn,sputnik} targets structural sparsity in
graphs or pruned weights; structured weight pruning~\cite{sparse24} exploits
fixed patterns; sparse-format compilers~\cite{taco,sparsetir} encode sparsity
in tensor formats. DPACS~\cite{dpacs} targets the same dynamic 2D spatial
sparsity but designs a custom dataflow accelerator to handle the resulting
irregular access patterns.

Row-indexed operand loads are an established implementation technique:
CUTLASS fuses gather and scatter into GEMM~\cite{cutlass}, mixture-of-experts
kernels read tokens through scattered indices inside a grouped
GEMM~\cite{scattermoe,megablocks}, and the Blackwell TMA gathers rows by
index~\cite{ptxisa}. These kernels use the indirection to avoid a copy, but
do not characterize its cost against the dense kernel, nor face the
overlapping receptive fields that scattering convolution outputs disrupts. We
show that for convolution on a dense input grid the indirection leaves the
reduction identical to dense, so the residual gap is a per-layer fixed cost
rather than lost throughput (\S\ref{sec:char}).

Selecting kernels by problem size is equally established. Compilers and
inference engines for dynamic shapes tune kernels over shape ranges and
dispatch among them at run time~\cite{dietcode,nimble,tensorrt}, GEMM
libraries choose a schedule per problem size~\cite{streamkpp}, and DA-MoE
selects fused mixture-of-experts kernels on the device from each layer's
token distribution~\cite{damoe}. These systems serve problems whose size
changes per request or batch and whose kernels run long enough to absorb a
selection step. Masked convolution in high-rate perception changes its size
at every layer of every frame, and its layers last microseconds, so each
decision point competes with the gain it buys (\S\ref{sec:char:cost}).
