\section{Evaluation}
\label{sec:eval}

\subsection{Experimental Setup}
\label{sec:eval:setup}

We evaluate \sysname across four perception models, three mask sources, four
GPU platforms, and three competing execution paradigms. The evaluation asks
four questions: (1)~does \sysname reduce full-model latency relative to the
fastest available path, (2)~how effectively does it convert required-work
reduction into latency reduction, (3)~what overhead does worklist construction
add, and (4)~does replacing the masked-convolution backend change task output
or accuracy?

\subsubsection{Platforms}

We evaluate four representative GPU platforms: two embedded SoCs (Jetson
Xavier NX and Jetson AGX Orin), a laptop-class mobile GPU (RTX~4070 Laptop),
and a desktop GPU (RTX~3080). These devices cover the hardware classes
commonly used for onboard deployment and robotics development. The two Jetson
systems anchor our target deployment setting, while the discrete GPUs test
whether \sysname generalizes beyond embedded SoCs.

\subsubsection{Models, Tasks, and Mask Sources}
Our selected workloads span three robotic perception tasks:
\begin{itemize}
  \item \textbf{Event-based optical flow.}
        We evaluate FireFlowNet~\cite{fireflownet}, a lightweight event-based
        optical-flow model that delivers high inference rates while retaining
        competitive accuracy, on MVSEC~\cite{mvsec}. MVSEC contains event-camera
        sequences and corresponding ground-truth flow from indoor quadrotor
        flight and outdoor driving. Following Ev-Conv~\cite{evconv},
        consecutive 50-ms windows advance by 1~ms; events entering or leaving
        the window form the sparse increment from which we derive layer masks.
        We calibrate the sparsification policy on
        \texttt{indoor\_flying1} and evaluate on the other three sequences.

  \item \textbf{Video object detection.}
        We evaluate YOLOv8n and YOLOv8m~\cite{yolov8} on MOT16~\cite{mot16}, a
        collection of crowded pedestrian videos with annotated person boxes.
        Both models produce bounding boxes and confidence scores, while their
        different scales expose how model size affects sparse-execution
        efficiency. DeltaCNN~\cite{deltacnn} supplies the temporal mask
        mechanism by propagating thresholded activation deltas between
        successive frames.

  \item \textbf{Human pose estimation.}
        We use the DynConv pose model~\cite{dynconv} on MPII~\cite{mpii}, which
        depicts people performing diverse activities and annotates their 2D
        body joints. The model predicts joint heatmaps; its learned spatial
        gates provide input-dependent masks at gated blocks.
\end{itemize}

Table~\ref{tab:models} summarizes their models and evaluation scales.
We use official weights for all four models~\cite{fireflownet,yolov8,dynconv}. 
For each workload, we fix these weights, inputs, and upstream mask
policy; the sparse paths receive the same resulting layer masks and differ
only in their masked-convolution backend.

\subsubsection{Execution Baselines}

We compare \sysname against three FP32 execution paths established by prior
work.

\begin{itemize}
  \item \textbf{Dense} uses the native PyTorch/cuDNN backend~\cite{cudnn} with sparse execution disabled.

  \item \textbf{Tile skipping} follows the tile-sparse execution established
        by SBNet, Ev-Conv, and DeltaCNN~\cite{sbnet,evconv,deltacnn}.

  \item \textbf{Gather-scatter} uses the original DynConv CUDA backend for
        human pose~\cite{dynconv} and an implementation equivalent to MMCV
        \texttt{MaskedConv2d} for FireFlowNet and YOLO~\cite{mmcv}.
\end{itemize}

\subsubsection{Metrics and Methodology}

Our primary metric is full-model GPU latency. The timed region includes mask
propagation, worklist construction, all network operators, and output update,
but excludes host-to-device input transfer, calibration, autotuning, and the
one-time dense state initialization required by incremental models. We use
CUDA events on the model's compute stream and process complete held-out
sequences rather than isolated synthetic frames. Each sequence is repeated
three times; we retain per-frame samples and report both aggregate latency and
dispersion.

To explain latency, we report the required-work ratio $\rho_{\mathrm{work}}$,
useful-compute ratio $\eta$, convolution throughput, and the construction
fraction of operator latency. Throughput here isolates the compute kernel;
construction is reported separately as a fraction of operator latency, so
readers can reconstruct the inclusive $T$ of
\S\ref{sec:bg:gap}. We aggregate $\eta$ as total active FLOPs over total
scheduled FLOPs across all convolution layers, so each layer contributes in
proportion to the work it actually schedules. Because layers differ in cost, an unweighted
average of layer activities misstates the work a mask removes, so we weight each
layer by its dense MAC count,
\begin{equation}
  \rho_{\mathrm{work}} =
  \frac{\sum_l \alpha^l W^l_{\mathrm{dense}}}
       {\sum_l W^l_{\mathrm{dense}}},
  \qquad
  \alpha^l=\frac{\|M^l\|_0}{H^l_{out}W^l_{out}},
  \label{eq:work-ratio}
\end{equation}
where $W^l_{\mathrm{dense}}$ is the dense MAC count of layer $l$. Task quality is measured with
Average Endpoint Error (AEE) for optical flow, detection AP against the fixed
evaluation references for YOLO, and PCKh for human pose. Accuracy comparisons
use the same masks and operating point as latency measurements; they evaluate
the upstream policy, while operator correctness is checked separately against
dense convolution at every active output.
