\subsection{Tile-Local Worklist Construction}
\label{sec:design:construct}
\label{sec:design:construct:compact}

Constructing a tight schedule already requires a scan of the output grid, but
the resulting coordinates must also retain enough spatial structure for
efficient consumption. Globally stable compaction preserves the complete dense
traversal order but requires a prefix scan or another pass to obtain
device-wide offsets; per-coordinate appends avoid that coordination but scatter
neighboring positions. Materializing active receptive fields, as gather-scatter
does, regularizes the compute input at the cost of feature traffic proportional
to the active count and $k^2C_{in}$. The useful middle ground is therefore a
metadata-only schedule with local rather than global ordering.

\sysname realizes this middle ground with contiguous, tile-local worklist
segments. Because the number of active positions is not known before the pass,
it preallocates a coordinate buffer with capacity
$|\mathcal{G}|=H_{out}W_{out}$, the static upper bound on
$|\mathcal{W}|$. Algorithm~\ref{alg:construct} details the resulting single
pass. Line~1 initializes the device-resident length counter. Lines~2--7
partition the output grid into $B_\tau\times B_\tau$ construction tiles, derive
the corresponding entries of $M_{out}$ using Eq.~\ref{eq:mask}, and compact
each tile's active coordinates into a local sequence $\mathcal{P}_\tau$ in
dense-traversal order. When a learned gate supplies $M_{out}$
directly~\cite{dynconv,dgnet}, Lines~4--5 are omitted and Line~7 compacts the
supplied mask. Lines~8--11 count the compacted coordinates, atomically reserve
$[\mathrm{base},\mathrm{base}+n_\tau)$ from the counter, and copy
$\mathcal{P}_\tau$ into that interval. After all tiles complete, the reserved
intervals collectively store $\mathcal{W}$, and the counter records
$n_{\mathcal{W}}$. Because the layer shape fixes the buffer capacity and launch
geometry while only the device observes the data-dependent length, construction
requires no runtime allocation or host-visible active count.

To relate the worklist to the useful-compute ratio of
Eq.~\ref{eq:efficiency-framework}, we insert its length $n_{\mathcal{W}}$ between the
required-position count and the issued-slot count. For
$n_{\mathcal{W}}>0$,
\begin{equation}
  \eta
  = \underbrace{\frac{\|M_{out}\|_0}{n_{\mathcal{W}}}}_{\eta_{\mathrm{construct}}}
  \cdot
  \underbrace{\frac{n_{\mathcal{W}}}{|\mathcal{C}|}}_{\eta_{\mathrm{compute}}} .
  \label{eq:eta-decomp}
\end{equation}
Here, $\eta_{\mathrm{construct}}$ compares required positions with worklist
entries, while $\eta_{\mathrm{compute}}$ compares worklist entries with issued
slots. We analyze the former here and the latter after defining the compute
organization in \S\ref{sec:design:compute}. The factorization decomposes
$\eta$ only; all stage costs remain reflected in throughput~$T$.

Because construction tiles partition the output grid and use disjoint
reservations, each active coordinate appears exactly once, so
$n_{\mathcal{W}}=\|M_{out}\|_0$. Fresh construction therefore has
$\eta_{\mathrm{construct}}=1$ for a nonempty worklist. Coverage constrains
membership rather than order, so tile reservation order does not affect
correctness; traversal order within each interval is retained for locality.

\begin{algorithm}[t]
\caption{Tile-Local Worklist Construction}
\label{alg:construct}
\begin{algorithmic}[1]
\REQUIRE Input mask $M_{in}$, output grid $\mathcal{G}$, tile size $B_\tau$
\ENSURE Mask $M_{out}$, worklist $\mathcal{W}$, length
        $n_{\mathcal{W}}=|\mathcal{W}|$
\STATE $n_{\mathcal{W}} \leftarrow 0$
\FOR{each $B_\tau \times B_\tau$ spatial tile $\tau$ \textbf{in parallel}}
  \FOR{each position $p \in \tau$ \textbf{in parallel}}
    \STATE $\mathrm{active}(p) \leftarrow \exists\, r \in \mathcal{N}(p): M_{in}[r] = 1$
    \STATE $M_{out}[p] \leftarrow \mathrm{active}(p)$
  \ENDFOR
  \STATE $\mathcal{P}_\tau \leftarrow \textsc{Compact}(\tau,\,M_{out})$
  \STATE $n_\tau \leftarrow |\mathcal{P}_\tau|$
  \STATE $\mathrm{base} \leftarrow
         \operatorname{AtomicAdd}(n_{\mathcal{W}},n_\tau)$
  \FOR{each $0\le j<n_\tau$ \textbf{in parallel}}
    \STATE $\mathcal{W}[\mathrm{base}+j] \leftarrow \mathcal{P}_\tau[j]$
  \ENDFOR
\ENDFOR
\end{algorithmic}
\end{algorithm}

\sysname thus confines its ordering guarantee to each contiguous segment:
coordinates retain the tile's dense traversal, while independently reserved
segments provide no cross-boundary locality guarantee. A compute
tile of $B_M$ positions (the output-position tile width used by the compute
stage, \S\ref{sec:design:compute}) may therefore span coordinates from multiple construction segments when
segments are shorter than $B_M$; the preserved locality is intra-segment
contiguity, not compute-tile-to-construction-tile alignment. As shown in
\S\ref{sec:eval:ablation-sensitivity}, this tile-local order achieves compute-stage
throughput comparable to global ordering, making the additional ordering pass
an unfavorable end-to-end trade-off.

\subsection{Cross-Operator Worklist Reuse}
\label{sec:design:reuse}

Each construction pass examines all $H_{out}W_{out}$ positions and, when
deriving $M_{out}$ from $M_{in}$, performs $O(k^2)$ mask work per position.
This channel-independent grid scan contrasts with required convolution work,
which scales with the active ratio, spatial extent, and both channel
dimensions. Repeating the scan
across same-grid layers that introduce no new required positions is therefore
redundant. \sysname instead amortizes construction over each compatible layer
sequence by reusing one worklist across its operators.

For layer $l$, let $\mathcal{G}^l$ denote its output grid, $M^l_{out}$ its
output mask, $\mathcal{W}^l$ its worklist, and $n^l_{\mathcal{W}}$ its
device-resident length. \sysname propagates the mask and worklist metadata
alongside the feature tensor. From layer semantics, \sysname statically infers
that consecutive layers are reuse-compatible when
$\mathcal{G}^{l+1}=\mathcal{G}^l$ and
\begin{equation}
  \{p\in\mathcal{G}^{l+1} \mid M^{l+1}_{out}[p]=1\}
  \subseteq
  \{p\in\mathcal{G}^l \mid M^l_{out}[p]=1\} .
  \label{eq:reuse-condition}
\end{equation}
Because $\mathcal{W}^l$ covers $M^l_{out}$,
Eq.~\ref{eq:reuse-condition} guarantees coverage for $M^{l+1}_{out}$.
\sysname therefore forwards $\mathcal{W}^{l+1}=\mathcal{W}^l$ and
$n^{l+1}_{\mathcal{W}}=n^l_{\mathcal{W}}$ without reconstruction and applies
the condition recursively at each subsequent layer.

Equality in Eq.~\ref{eq:reuse-condition} covers same-grid $1\times1$
convolutions, mask-preserving activations, and inference-time normalization,
leaving $\eta_{\mathrm{construct}}$ unchanged. Strict inclusion can result from
mask-narrowing operators in the upstream policy, such as the activation-fused
update truncation that DeltaCNN uses to increase downstream
sparsity~\cite{deltacnn}. The inherited worklist remains a valid superset,
trading a lower $\eta_{\mathrm{construct}}$ for one fewer construction pass
without violating coverage. Because compute gates all output writes by the
exact mask, positions scheduled but no longer active under the current mask
participate in reduction yet produce no store; the superset schedule therefore
cannot alter any inactive position's observable state.

A change in the output grid violates the geometry constraint, while
receptive-field expansion may violate Eq.~\ref{eq:reuse-condition} by
introducing positions outside the upstream mask; either case invokes the
construction pass of \S\ref{sec:design:construct:compact} to emit a new tight
worklist. A lower $\eta_{\mathrm{construct}}$ alone does not trigger
reconstruction because tightening a valid superset would pay another grid scan.
Common receptive-field-expanding layers such as $3\times3$ convolutions still
create rebuild points throughout the network, leaving device-resident worklist
lengths variable across layers and frames. Compute must therefore handle a
dynamic problem size.

\subsection{On-Device Adaptive Stream-K Execution}
\label{sec:design:compute}

Construction and reuse fix $\eta_{\mathrm{construct}}$; the compute stage
controls $\eta_{\mathrm{compute}}$ and throughput~$T$. Dense convolution maps
to an implicit GEMM with $M$ output positions, $N=C_{out}$ output channels, and
reduction depth $K=k^2 C_{in}$. An output tile covers $B_M$ positions and
$B_N$ channels; the reduction over $K$ proceeds in steps of $B_K$.
In the standard \emph{data-parallel} decomposition, each of the
$\lceil M/B_M\rceil \times \lceil N/B_N\rceil$ output tiles is assigned to one
thread block, which performs the full $K$ reduction; split-$K$ instead
replicates each tile across $S_k$ blocks that each reduce a disjoint
$K$-slice. Because all three dimensions
are static functions of the layer shape, the output tile shape $(B_M, B_N)$,
reduction step $B_K$, and any $K$-axis parallelism (split-$K$) can be selected
once offline by profiling each candidate at the known problem size and keeping
the fastest. This shape-specific calibration is how dense GEMM libraries (e.g., cuDNN) sustain
high throughput.

In worklist convolution, $N$ and $K$ remain static, but the
$M$~dimension becomes $n_{\mathcal{W}}$, the device-resident worklist length
written by construction, which varies by an order of magnitude or more across
frames of a single layer. The offline assumption breaks: a single configuration
cannot serve the full range. Two failure regimes bracket the problem. When
activity is high and output tiles are plentiful, $K$-axis parallelism adds
coordination and accumulation overhead without improving occupancy. When
activity is low and tiles are scarce, data-parallel execution leaves
streaming multiprocessors (SMs) without work because the tile count no longer
fills a full \emph{wave} (the set of thread blocks that co-reside across all
SMs), referred to as the problem of wave quantization.
Adapting between these regimes requires knowing $n_{\mathcal{W}}$, which is device-resident, and transferring it to the host inserts a
per-operator synchronization on the critical path.

\sysname builds on Stream-$K$~\cite{streamk}, the established solution to wave
quantization in dense GEMM and a non-uniform generalization of split-$K$.
Uniform split-$K$ replicates every tile $S_k$ times to create more schedulable
units, but a $S_k$ high enough for low tile counts overburdens high-tile-count
regimes with unnecessary partial reduction. Stream-$K$ avoids this by launching
a \emph{persistent grid} of blocks equal to the device's SM occupancy (not the
tile count), each consuming tiles through a grid-stride loop, and splitting
$K$ non-uniformly: complete-wave tiles are handled one block per tile, while
the partial tail wave's tiles distribute their $K$-iterations across blocks
that have finished the complete waves and would otherwise sit idle. The wave
boundary that governs this split is a static function of the tile count in
Stream-$K$. In worklist convolution the tile count changes every frame, so the
boundary shifts with it. This shifting boundary is the operating point of
\sysname's \emph{on-device adaptive Stream-$K$ execution}: the compute kernel
reads the exact worklist length on the device, determines the current wave
boundary, and applies data-parallel, uniform split-$K$, or non-uniform hybrid
Stream-$K$ decomposition accordingly, without host involvement.

Because the host cannot observe $n^l_{\mathcal{W}}$ without synchronization,
every host-visible launch parameter must be independent of the current worklist
length. \sysname therefore fixes the tile configuration $(B_M, B_N, B_K)$ per
layer at deployment; the GEMM pipeline is identical to dense implicit GEMM
except that the coordinate source is replaced by the worklist, gathering input
from the dense feature tensor by worklist coordinates rather than contiguous
grid traversal. What changes per frame is how the $K$~reduction across output tiles is assigned
to thread blocks. Within the compute kernel, \sysname reads the current
$n^l_{\mathcal{W}}$ and selects among three decomposition modes derived from
Stream-$K$:
\begin{itemize}
  \item \emph{Data-parallel}: each block owns a complete output tile and
    reduces the full $K$~range.
  \item \emph{Aligned split-$K$}: each output tile is replicated across
    $S_k$~blocks, each reducing a disjoint $K$-slice, multiplying the
    schedulable unit count to fill the device.
  \item \emph{Hybrid Stream-$K$}: a data-parallel prefix handles complete
    waves; a streaming tail distributes the remaining tiles' $K$-iterations
    across one wave of blocks, eliminating partial-wave waste without applying
    the streaming overhead to the entire grid.
\end{itemize}

Both the tile configuration and the optimal mode for each layer and worklist
length are calibrated offline. For each layer~$l$, \sysname first selects the
tile configuration~$\hat{q}^l=(B_M,B_N,B_K)$ from a small
catalog~$\mathcal{Q}$ by profiling each at the full worklist
$\mathcal{W}^l_{\mathrm{full}}$ (all $|\mathcal{G}^l|$ output positions) and
keeping the fastest, ensuring competitiveness with dense execution as a
baseline. Let $t(q,\mathcal{W})$ denote the minimum kernel latency of
configuration~$q$ on worklist~$\mathcal{W}$ over all mode candidates:
\begin{equation}
  \hat{q}^l
  = \arg\min_{q\in\mathcal{Q}}\;
    t(q,\;\mathcal{W}^l_{\mathrm{full}}).
  \label{eq:tileconfig}
\end{equation}
Second, within~$\hat{q}^l$, \sysname builds a \emph{policy table}~$P^l$
indexed by tile count $s=\lceil n^l_{\mathcal{W}}/B_M\rceil$. For each~$s$ it
profiles every candidate decomposition mode~$m$ (one of the three above) and
split factor~$S_k$ using a synthetic
worklist~$\mathcal{W}_s$ of length~$s\cdot B_M$ and records the fastest
combination:
\begin{equation}
  P^l[s]
  = \arg\min_{m,\,S_k}\;
    t(\hat{q}^l,\;\mathcal{W}_s,\;m,\;S_k),
  \label{eq:policy}
\end{equation}
where the minimization ranges over the three modes and their compatible split
factors.
Both calibrations search small candidate sets over measured
latency and run once at deployment; the tile configuration fixes per-tile throughput,
while the policy table adapts the $K$-splitting strategy to each possible tile
count.

At runtime, the compute kernel reads $n^l_{\mathcal{W}}$ from the device scalar
written by construction, computes $s=\lceil n^l_{\mathcal{W}}/B_M\rceil$, and
indexes~$P^l[s]$ to obtain the current mode and split factor
(Algorithm~\ref{alg:streamk}, Lines~1--3). All three modes share the same
gather-at-load reduction datapath; only the block-to-work mapping differs
(Algorithm~\ref{alg:streamk}, Lines~4--20).

When split-$K$ or hybrid Stream-$K$ assigns multiple blocks to disjoint
$K$-ranges of the same output tile, each block writes its partial accumulator
(a $B_M \times B_N$ fragment in the accumulation precision, typically FP32) to
a pre-allocated workspace slot for that tile. The workspace is sized to
$\max(S_k) \times |\mathbf{y}^l|$ elements per layer, where $\max(S_k)$ is
the largest split factor in $P^l$. A per-tile completion counter tracks how many contributors
have finished; the last block to arrive loads all partial fragments, reduces
them, applies the output epilogue, and writes the final result
(Algorithm~\ref{alg:streamk}, Lines~21--23). No device-wide barrier is needed;
data-parallel tiles bypass the workspace entirely and write output directly.

\begin{algorithm}[t]
\caption{On-Device Adaptive Stream-$K$ Worklist Computation}
\label{alg:streamk}
\begin{algorithmic}[1]
\REQUIRE Worklist $\mathcal{W}$ (device-resident), policy table~$P$,
         persistent grid of $G$ blocks, workspace~$S$
\ENSURE Output $\mathbf{y}$ (updated at worklist positions)
\STATE $n_{\mathcal{W}} \leftarrow$ \textbf{read} worklist length from device memory
\STATE $s \leftarrow \lceil n_{\mathcal{W}} / B_M \rceil$
\STATE $(\mathit{mode}, S_k) \leftarrow P[s]$
       \hfill\COMMENT{precomputed policy lookup}
\IF{$\mathit{mode} = \textsc{DataParallel}$}
  \FOR{$\mathrm{tile} = \mathrm{bid},\; \mathrm{bid}{+}G,\; \ldots < s$}
    \STATE \textsc{Compute}($\mathcal{W}$, $\mathrm{tile}$,
           $K_{\mathrm{range}}=[0,K)$) $\to$ $\mathbf{y}$
  \ENDFOR
\ELSIF{$\mathit{mode} = \textsc{AlignedSplitK}$}
  \STATE $n_{\mathrm{units}} \leftarrow s \times S_k$
  \FOR{$u = \mathrm{bid},\; \mathrm{bid}{+}G,\; \ldots < n_{\mathrm{units}}$}
    \STATE $\mathrm{tile} \leftarrow \lfloor u / S_k \rfloor$;
           $K_{\mathrm{range}} \leftarrow \textsc{Partition}(K, S_k, u \bmod S_k)$
    \STATE \textsc{Accumulate}($S$, $\mathcal{W}$, $\mathrm{tile}$,
           $K_{\mathrm{range}}$)
  \ENDFOR
\ELSE[Hybrid Stream-$K$]
  \STATE $s_{\mathrm{dp}} \leftarrow s - (s \bmod G)$
         \hfill\COMMENT{full-wave prefix}
  \FOR{$\mathrm{tile} = \mathrm{bid},\; \mathrm{bid}{+}G,\; \ldots < s_{\mathrm{dp}}$}
    \STATE \textsc{Compute}($\mathcal{W}$, $\mathrm{tile}$,
           $K_{\mathrm{range}}=[0,K)$) $\to$ $\mathbf{y}$
  \ENDFOR
  \STATE $I_{\mathrm{tail}} \leftarrow (s - s_{\mathrm{dp}}) \times K$
  \FOR{$i = \mathrm{bid},\; \mathrm{bid}{+}G,\; \ldots < I_{\mathrm{tail}}$}
    \STATE $(\mathrm{tile}, K_{\mathrm{range}}) \leftarrow
           \textsc{Unflatten}(i, s_{\mathrm{dp}}, K)$
    \STATE \textsc{Accumulate}($S$, $\mathcal{W}$, $\mathrm{tile}$,
           $K_{\mathrm{range}}$)
  \ENDFOR
\ENDIF
\IF{$S_k > 1$ \textbf{or} $\mathit{mode} = \textsc{StreamK}$}
  \IF{\textsc{LastArriver}($\mathrm{tile}$)}
    \STATE \textsc{Reduce}($S$, $\mathrm{tile}$) $\to$ $\mathbf{y}$
  \ENDIF
\ENDIF
\end{algorithmic}
\end{algorithm}
