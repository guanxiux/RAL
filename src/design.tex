\section{\sysname Design}
\label{sec:design}

%% ================================================================
\subsection{Overview}
\label{sec:overview}
% fig:overview is defined in characterization.tex so that it floats to the top of the Design section page.
\sysname exploits the fact that dense tiled convolution is driven by output
coordinates: each coordinate determines the receptive-field reads and output
write, while the reduction over channels and kernel offsets remains regular.
Replacing the dense coordinate sequence with an active-output worklist
introduces position-level selectivity into the tiled pipeline without altering
the reduction datapath (Figure~\ref{fig:overview}).

The characterization shows that a worklist tile keeps the per-tile throughput
of dense execution (\S\ref{sec:char:reduction}). What remains between this
selectivity and end-to-end latency reduction are the costs isolated by
Insights~4 and~5: each construction pass costs nearly constant time whatever
the activity (\S\ref{sec:char:bound}), and following the worklist length requires a choice
of configuration that only the device can make (\S\ref{sec:char:cost}).
Figure~\ref{fig:overview} shows how \sysname handles both on the running
example. Construction (\ding{192}, \S\ref{sec:design:construct}) builds the
worklist from $M_{out}$ in one pass over mask metadata, and the same pass
selects the tile configuration of every layer that reads the worklist
(\S\ref{sec:design:select}). Later operators with the same geometry reuse the
worklist (\ding{193}, \S\ref{sec:design:reuse}), so neither construction
nor selection repeats at every layer. The compute stage (\ding{194}, \S\ref{sec:design:compute})
consumes the worklist in a persistent grid that reads its length from device
memory. All stages run in one per-frame CUDA graph (bottom of
Figure~\ref{fig:overview}): construction enables, on the device, the selected
candidate of every layer that reads the worklist (the small-tile nodes of
$\ell$ and $\ell{+}1$), so the frame needs no host synchronization between
layers.

\subsection{Tile-Local Worklist Construction}
\label{sec:design:construct}
\label{sec:design:construct:compact}

Construction turns $M_{in}$ into $M_{out}$ and the worklist $\mathcal{W}$ in
one pass over the layer's output grid, reading and writing only mask metadata,
never features or weights (Algorithm~\ref{alg:construct}). The pass partitions
the grid into construction tiles, one per CTA. Each CTA derives its tile's
entries of $M_{out}$ by Eq.~\ref{eq:mask} (lines~3--6; a learned gate supplies
them directly), compacts the tile's active positions in dense traversal order
(line~7), and reserves a contiguous segment of $\mathcal{W}$ with one atomic
add on a device-resident length counter $n_{\mathcal{W}}$ (line~9). The buffer holds $|\mathcal{G}|$ entries, the static
upper bound on $n_{\mathcal{W}}$, so construction allocates nothing at run time
and $n_{\mathcal{W}}$ never leaves the device. Every active position lands in
exactly one segment, so the worklist is exact: $n_{\mathcal{W}}=\|M_{out}\|_0$.

\begin{algorithm}[t]
\caption{Tile-Local Worklist Construction}
\label{alg:construct}
\begin{algorithmic}[1]
\REQUIRE Input mask $M_{in}$, output grid $\mathcal{G}$
\ENSURE Mask $M_{out}$, worklist $\mathcal{W}$, length
        $n_{\mathcal{W}}=|\mathcal{W}|$
\STATE $n_{\mathcal{W}} \leftarrow 0$
\FOR{each construction tile $\tau\subset\mathcal{G}$ \textbf{in parallel}}
  \FOR{each position $p \in \tau$ \textbf{in parallel}}
    \STATE $\mathrm{active}(p) \leftarrow \exists\, r \in \mathcal{N}(p): M_{in}[r] = 1$
    \STATE $M_{out}[p] \leftarrow \mathrm{active}(p)$
  \ENDFOR
  \STATE $\mathcal{P}_\tau \leftarrow \textsc{Compact}(\tau,\,M_{out})$
  \STATE $n_\tau \leftarrow |\mathcal{P}_\tau|$
  \STATE $\mathrm{base} \leftarrow
         \operatorname{AtomicAdd}(n_{\mathcal{W}},n_\tau)$
  \FOR{each $0\le j<n_\tau$ \textbf{in parallel}}
    \STATE $\mathcal{W}[\mathrm{base}+j] \leftarrow \mathcal{P}_\tau[j]$
  \ENDFOR
\ENDFOR
\end{algorithmic}
\end{algorithm}

The resulting order is tile-local: dense within each segment, arrival order
across segments. A globally ordered worklist would need a device-wide prefix
scan or a second pass, and order has a negligible effect on the compute
stage (Insight~3). What remains is the cost of the pass itself: it scans the whole
grid, so it is fixed by the layer shape while the convolution it enables
shrinks with activity and channel width.

\subsection{Cross-Operator Worklist Reuse}
\label{sec:design:reuse}

\sysname therefore builds a worklist only where the active set can grow. Layer
$l+1$ reuses the worklist of layer $l$ when it keeps the output grid and cannot
activate a position outside layer $l$'s active set:
\begin{equation}
  \mathcal{G}^{l+1}=\mathcal{G}^{l},\qquad
  \{p \mid M^{l+1}_{out}[p]=1\} \subseteq \{p \mid M^{l}_{out}[p]=1\}.
  \label{eq:reuse-condition}
\end{equation}
The condition depends on operator types, not on mask values ($1\times1$
convolutions, activations, and normalization satisfy it), so model conversion
marks reuse edges once. A reused worklist need not be exact. To track where
issued work goes, we factor the useful-compute ratio of
Eq.~\ref{eq:efficiency-framework} into a construction and a compute term:
\begin{equation}
  \eta
  = \underbrace{\frac{\|M_{out}\|_0}{n_{\mathcal{W}}}}_{\eta_{\mathrm{construct}}}
  \cdot
  \underbrace{\frac{n_{\mathcal{W}}}{|\mathcal{C}|}}_{\eta_{\mathrm{compute}}} .
  \label{eq:eta-decomp}
\end{equation}
A freshly constructed worklist has $\eta_{\mathrm{construct}}=1$. When the
upstream policy narrows a mask, as DeltaCNN's update truncation
does~\cite{deltacnn}, the reused worklist becomes a superset
($\eta_{\mathrm{construct}}<1$); the extra positions cost compute time but do
not affect the output, because only positions active in the layer's own
$M_{out}$ are written. A new grid or a receptive field wider than one position
marks a rebuild point. Rebuild points recur at every $3\times3$ convolution, so
the worklist length changes from layer to layer as well as from frame to frame,
and the compute stage must consume a length that only the device knows.

\subsection{Worklist-Driven Tiled Compute}
\label{sec:design:compute}

The compute stage keeps the dense kernel's implicit-GEMM mapping and changes
only which output positions a tile covers. Dense convolution maps to a GEMM
with $M$ output positions, $N=C_{out}$, and reduction depth $k^2C_{in}$;
\sysname sets $M=n_{\mathcal{W}}$, so GEMM row $i$ is output position
$\mathcal{W}[i]$. A configuration $q$ is one point of the dense kernel's
configuration space: the tile shape $B_M\times B_N$, the reduction step $B_K$,
and the remaining tiling parameters such as warp layout, pipeline depth, and a
reduction split within or across CTAs~\cite{cutlass}. \sysname adds no
parameter to this space.

\begin{algorithm}[t]
\caption{Worklist-Driven Tiled Compute (configuration $q$)}
\label{alg:compute}
\begin{algorithmic}[1]
\REQUIRE Input $\mathbf{x}$ on the dense grid, weights $\mathbf{f}$, output
  mask $M_{out}$, worklist $\mathcal{W}$ and length $n_{\mathcal{W}}$ in device
  memory; tile count
  $N_t=\lceil n_{\mathcal{W}}/B_M\rceil\lceil C_{out}/B_N\rceil$; $P$ CTAs
\ENSURE Output $\mathbf{y}$ at every active position
\FOR{each CTA $g=0,\dots,P-1$ \textbf{in parallel}}
  \FOR{$t=g,\,g+P,\,g+2P,\dots$ while $t<N_t$}
    \STATE $(b_m,b_n)\leftarrow$ output tile $t$
    \STATE $R\leftarrow\mathcal{W}[b_mB_M:(b_m+1)B_M]$ \COMMENT{active positions}
    \STATE $\mathbf{Y}\leftarrow\mathbf{0}_{B_M\times B_N}$
    \FOR{each receptive-field offset $i=1,\dots,k^2$}
      \FOR{each channel slice $s=1,\dots,\lceil C_{in}/B_K\rceil$}
        \STATE $\mathbf{X}\leftarrow$ load $\mathbf{x}[\mathcal{N}_i(p)]$ for $p\in R$, slice $s$
        \STATE $\mathbf{B}\leftarrow$ load $\mathbf{f}_i$, slice $s$, column block $b_n$
        \STATE $\mathbf{Y}\leftarrow\mathbf{Y}+\mathbf{X}\mathbf{B}$
      \ENDFOR
    \ENDFOR
    \STATE write $\mathbf{Y}$ to $\mathbf{y}$ at each $p\in R$ with $M_{out}[p]=1$
  \ENDFOR
\ENDFOR
\end{algorithmic}
\end{algorithm}

Because $n_{\mathcal{W}}$ exists only on the device, the host cannot launch
the right number of tiles. Algorithm~\ref{alg:compute} instead launches a
persistent grid of $P$ CTAs, sized by the configuration and the GPU alone,
which reads $n_{\mathcal{W}}$ from device memory and strides over the output
tiles it implies (line~2); CTAs beyond the tile count exit immediately, so one
static launch serves every length and every frame. Each tile reads its $B_M$
worklist entries once (line~4); the reduction (lines~6--12) then walks the
kernel offsets and channel slices exactly as dense execution does. Because the
input stays a dense grid, every neighbor of an active position lies at a fixed
offset from that position, so the worklist sets only each row's base address
and the addresses inside the reduction loop remain affine. The irregularity is
$B_M$ indexed loads per tile outside the reduction, while channel-contiguous
loads and weight-tile reuse are those of the dense kernel (Insight~2). The
epilogue stores only positions active in $M_{out}$ (line~13), so the padding
of the last tile and the superset entries inherited through reuse produce no
writes. That padding is the only issued work beyond the worklist:
$\eta_{\mathrm{compute}}=n_{\mathcal{W}}/(\lceil n_{\mathcal{W}}/B_M\rceil
B_M)$.

What a static grid cannot fix is the configuration itself: the fastest $q$
depends on $n_{\mathcal{W}}$ (Insight~1).

\subsection{Cost-Aware Tile Selection}
\label{sec:design:select}

Following $n_{\mathcal{W}}$, however, costs time at every decision point
(Insight~5). \sysname therefore decides per layer whether, and how
finely, to follow the length, by weighing the expected gain of each additional
candidate configuration against its cost.

For layer $l$, an offline sweep on the target GPU measures the time $t_q(n)$
of every configuration $q$ in the space $\mathcal{Q}$ across worklist lengths
$n$; $t^{*}(n)=\min_{q\in\mathcal{Q}}t_q(n)$ is the per-length best. A
selection $S$ with $K$ candidates $q_1,\dots,q_K$ and thresholds
$0=\theta_0<\theta_1<\dots<\theta_K=|\mathcal{G}|+1$ runs $q_S(n)=q_k$ for
$\theta_{k-1}\le n<\theta_k$ and pays the GPU's per-layer cost of choosing
among $K$ candidates, $c(K)$ with $c(1)=0$, measured once on the same GPU.
Without a prior on the deployment's activity, the selection assumes $n$
uniform over $[1,|\mathcal{G}|]$ and maximizes the geometric-mean speedup, that
is, minimizes the expected log-slowdown relative to the per-length best:
\begin{equation}
  \hat{S}=\arg\min_{K,\,S}\ \mathbb{E}_{n}\!\left[\log
  \frac{t_{q_S(n)}(n)+c(K)}{t^{*}(n)}\right].
  \label{eq:select}
\end{equation}
Because $n$ is a scalar, the candidates partition a single range. On the
sweep's lengths $n_1<\dots<n_J$, with $L_q(u)$ the log term of
Eq.~\ref{eq:select} at $n_u$ and $w_u$ the probability mass of $n_u$'s
interval, the best expected cost $F_k(j)$ of covering the first $j$ lengths with
$k$ candidates obeys
\begin{equation}
  F_k(j)=\min_{i<j}\Big[F_{k-1}(i)+\min_{q\in\mathcal{Q}}\sum_{u=i+1}^{j}w_uL_q(u)\Big],
  \qquad F_0(0)=0,
  \label{eq:select-dp}
\end{equation}
and evaluating $F_K(J)$ for each $K$ yields $\hat{S}$ exactly. The gain of each
added candidate shrinks while $c(K)$ grows, so $K$ is an output of the
trade-off rather than a design constant.

At run time the decision must happen where $n_{\mathcal{W}}$ first exists,
without host involvement. The kernel that writes a layer's worklist learns
$n_{\mathcal{W}}$ when its last CTA finishes, compares it with the thresholds
of every layer that reads this worklist (the layer and the operators that
reuse it), and switches each to its selected candidate, when it differs from
the current one, before the compute launches. The design does not depend on how the
switch is performed: $c(K)$ is the cost of the cheapest device-side mechanism
the GPU offers (\S\ref{sec:impl}). As a result, $K$ differs across layers,
GPUs, and precisions: layers whose optimum shifts little keep one
configuration and pay nothing for selection;
\S\ref{sec:eval:ablation-sensitivity} shows that both ignoring the cost and
fixing one configuration fall short of this selection.
